# Visa Ease Solutions

The website for **Visa Ease Solutions**, a South African visa and travel assistance business. It helps travellers prepare and organise their visa applications, with Schengen visas as the lead speciality.

**Live site:** https://www.visaeasesolutions.co.za
**Built by:** [Olideen Technologies](https://olideentech.co.za)

The site is plain HTML, CSS and JavaScript. There is no framework, no build step and no database, so it is fast, cheap to host and easy to maintain.

## Running the site locally

Open the folder in a terminal and start a small web server, then visit the address it prints:

```bash
# Python
python -m http.server 8000      # then open http://localhost:8000

# or Node.js
npx serve .
```

Opening the HTML files directly also works for most things, but a local server is closer to the live site and is needed for the forms to send.

## Hosting and deployment

The site is hosted on **GitHub Pages**.

- **To publish a change:** commit it and push to `main`. GitHub rebuilds the site automatically, and the change is live in about a minute.
- **Settings:** in the repository, **Settings > Pages** is set to **Deploy from a branch**, `main`, `/ (root)`, with the custom domain `www.visaeasesolutions.co.za` and **Enforce HTTPS** on.
- **`CNAME`:** GitHub writes this file when the custom domain is saved in Settings. Do not delete or edit it by hand.
- **Before every commit:** run `git status` and check that no files show as deleted unexpectedly. Photos have been lost this way before.

**Moving to another host, such as Netlify:** upload the folder as it is. Leave the build command empty, set the publish directory to the root, add the custom domain, and turn on HTTPS. Netlify also serves `404.html` for missing pages automatically.

## Forms and EmailJS

The site has two forms. Both use the same code in `script.js` and the same EmailJS template.

| Form | Page | Purpose |
|---|---|---|
| Enquiry form (`#enquiry-form`) | `contact.html` | General questions and quote requests |
| Apply form (`#apply-form`) | `apply.html` | Starting an application, with visa type and destination |

### Settings

The EmailJS settings are at the top of `script.js`:

```js
const EMAILJS_CONFIG = {
  SERVICE_ID: 'service_globkhc',   // EmailJS > Email Services
  TEMPLATE_ID: 'template_naj3nzr', // "Contact Us" template
  PUBLIC_KEY: '6FzkylnerqPmcK3ry'  // EmailJS > Account > General > Public key
};
const DEMO_WHEN_UNCONFIGURED = false;
```

The public key is designed to be visible in website code. Never put the EmailJS **private** key in the site.

### Template variables

The "Contact Us" template uses these variables. Set the template's **Reply To** to `{{email}}`.

| Variable | Enquiry form | Apply form |
|---|---|---|
| `{{full_name}}` | Full name | First name and last name, joined |
| `{{whatsapp}}` | WhatsApp number | WhatsApp or contact number |
| `{{email}}` | Email address | Email address |
| `{{destination}}` | Destination country | Destination country |
| `{{purpose}}` | Purpose of travel | Visa type |
| `{{travel_dates}}` | Intended travel dates | Intended travel dates |
| `{{applicants}}` | Number of applicants | Number of applicants |
| `{{message}}` | Message | "Town or city: …", followed by the message |
| `{{consent}}` | `yes` | `yes` |
| `{{form_type}}` | `enquiry` | `apply` |
| `{{page}}` | Address of the page | Address of the page |

A good subject line is `New website {{form_type}} from {{full_name}}`.

### How the forms behave

- **Validation:** names, email, town (Apply form) and a South African number. `082 123 4567`, `+27 82 123 4567` and `27821234567` are all accepted, as are international numbers in `+` format.
- **Consent:** the POPIA consent checkbox is required, and its text links to the Privacy Policy.
- **Spam:** a hidden honeypot field (`company_website`) quietly drops bot submissions and is never sent. There is no reCAPTCHA.
- **Privacy:** the forms never ask for passport numbers, ID numbers or document uploads.
- **On success:** the form is replaced by a thank you message.
- **If sending fails, or a setting is missing:** the visitor sees "Sorry, we could not send your enquiry. Please try again or contact us on WhatsApp on 068 249 7759." Everything they typed stays in the form.
- **`DEMO_WHEN_UNCONFIGURED`:** must stay `false` on the live site. Setting it to `true` makes the forms show their success message without sending anything, which is only useful for local design testing.

## Apply Now links

Links to `apply.html` can preselect the destination and visa type, for example `apply.html?visa=tourist&country=canada`. The same `?country=` values also work on `contact.html`.

| Parameter | Accepted values |
|---|---|
| `visa` | `tourist`, `business`, `not-sure` |
| `country`, Schengen area | `schengen` (another Schengen country), `france`, `germany`, `italy`, `spain`, `netherlands`, `belgium`, `sweden` |
| `country`, other destinations | `canada`, `turkey`, `saudi-arabia`, `usa`, `ireland`, `china` |
| `country`, Africa | `nigeria`, `ghana`, `cote-divoire` |
| `country`, other | `other`, `not-sure` |

An unknown value is ignored and the field stays on its first option. The values are the `data-slug` attributes on each `<option>`, so a new destination needs a new `<option>` with its own `data-slug` in both forms.

**Links currently on the site:**
- **Home, "Countries we assist with":** `?country=canada`, `turkey`, `saudi-arabia`, `usa`, `ireland` and `china`. The Africa card links to plain `apply.html`, and the Schengen card links to `schengen-visas.html`.
- **Home, "Visa types we assist with":** `?visa=tourist` and `?visa=business`.
- **Schengen page, "Which visa fits your trip?":** `?visa=tourist&country=schengen` and `?visa=business&country=schengen`.

## SEO

Every page has a unique title and description, a canonical address, Open Graph and Twitter tags for link previews, favicons, and the business details as structured data (JSON-LD). The FAQ page also has FAQ structured data.

**These tags are generated, not written by hand.** To change any of them:

```bash
node tools/seo-heads.js   # edit the values at the top of this file first, then run it
node tools/seo-check.js   # must finish with "0 failed"
```

`tools/seo-heads.js` holds, in one place:
- **Pages:** each page's title and description.
- **`SITE`:** the site address.
- **`EMAIL`:** the business email.
- **The business details:** phone, hours, service area, social links and services.

Running it also rewrites `sitemap.xml` and `robots.txt`.

**Rules:**
- **Descriptions:** keep each between 140 and 155 characters.
- **The FAQ:** its visible answers and its structured data must match word for word. If you change a FAQ answer in `how-it-works.html`, change it in both places. The checker compares them.
- **Structured data:** use plain text only, with no HTML entities such as `&amp;`, and use full `https://` addresses.

After launch, submit `https://www.visaeasesolutions.co.za/sitemap.xml` in Google Search Console. The full SEO record is in [`docs/seo-section-6.md`](docs/seo-section-6.md).

## Design system

**Colours** (variables in `:root` in `style.css`):

| Variable | Colour | Used for |
|---|---|---|
| `--navy` | `#0F2557` | Headings, text, utility bar, footer |
| `--rose-deep` | `#A95252` | Buttons and script accents |
| `--rose` | `#D98B8B` | Decoration and borders (never text) |
| `--blush`, `--blush-soft` | `#F6DCD8`, `#FAE7E3` | Section backgrounds |
| `--cream` | `#FBEFEA` | Page background |
| `--gold` | `#C9A24B` | Passport illustration |
| `--wa`, `--wa-deep` | `#25D366`, `#1DA851` | Floating WhatsApp button and its hover state |

**Typography** (self-hosted in `assets/fonts/`):
- **Playfair Display (600, 700):** headings and the logo.
- **Allura:** script accents, such as "Assistance" and "Solutions".
- **Plus Jakarta Sans (400 to 700):** body text, buttons and navigation.

**Layout:**
- **Breakpoints:** mobile first, at 480px, 768px and 1024px. The full desktop navigation and the three and four column grids start at 1024px. One extra rule at 400px switches the utility bar between "Email" and the full address.
- **Utility bar:** visible on every screen size. Phones show the WhatsApp number and an email link. Tablets add the social icons. Desktops also show the "Specialising in Schengen visas" note.

**Accessibility:**
- **Contrast:** text meets WCAG AA, including over the photo backgrounds, which sit under a cream or navy overlay. The one exception is the white icon on the bright WhatsApp green, about 2:1, kept at the client's request because the colour is so recognisable.
- **Keyboard and tap use:** keyboard focus is always visible, and tap targets are at least 44px.
- **Screen readers:** icons are hidden from screen readers, and icon-only links have labels.

**Motion:** cards fade in gently as they scroll into view. All animation is switched off for visitors who choose reduced motion in their device settings.

## Content guidelines

These rules keep the site accurate, trustworthy and consistent. Follow them for any new copy.

- **Language:** South African English (specialising, organise, travellers), in warm, professional, full sentences.
- **Approval:** never promise or imply visa approval. Approval is solely at the discretion of the relevant embassy, consulate or immigration authority, and the site says so.
- **Visa types:** the business offers **tourist and business visas only**.
- **Pricing:** no prices are published. Every mention invites the visitor to ask for a quote.
- **Other destinations:** make no claims about whether South Africans need a visa for the non-Schengen destinations, and give no fees, rules or processing times for them unless they have been checked against official sources.
- **Lead time:** there is no fixed lead time. It depends on the destination and on how quickly the client provides documents.
- **Submission:** for certain applications, the business submits on the client's behalf. If the embassy, consulate or visa centre raises an issue, the client attends in person.
- **Reviews:** never publish invented reviews, statistics, accreditation or years of experience.
- **Tone around privacy and documents:** reassuring, not alarming. For example: "When it is time for documents, we will guide you through a simple, private way to share them."

## Common maintenance tasks

| Task | How |
|---|---|
| **Replace a photo** | Overwrite the file with one of the same name and size (800 × 600 for destination photos), then update its `alt` description in the HTML |
| **Change the business email** | Change `EMAIL` in `tools/seo-heads.js` and run it. Then replace the address in the eight HTML files (utility bar, mobile menu, footer, Home and Contact pages) |
| **Change the EmailJS account** | Update the three values at the top of `script.js` |
| **Edit a FAQ answer** | Change the visible answer and the matching JSON-LD answer in `how-it-works.html`, then run `node tools/seo-check.js` |
| **Change a page title or description** | Edit `tools/seo-heads.js`, run it, then run the checker |
| **Add a destination** | Add a card to "Countries we assist with" in `index.html`, add an `<option>` with a `data-slug` to the destination list in both `apply.html` and `contact.html`, and add it to `knowsAbout` in `tools/seo-heads.js` |
| **Show testimonials** | The section is hidden inside an HTML comment in `index.html`. Replace the sample reviews with real feedback, shared with written permission, delete the "Sample content" label, and remove the comment wrapper |
| **Update the link preview image** | Replace `assets/og-image.jpg` with a 1200 × 630 image. WhatsApp and Facebook cache previews, so test with a fresh link such as `/?v=2`, or use Facebook's Sharing Debugger |

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Forms say "Sorry, we could not send your enquiry" | EmailJS cannot send through its Gmail connection. In the browser's network tab, the request to `api.emailjs.com` returns an error such as 412. | In EmailJS, open **Email Services**, open the service, **Disconnect**, then **Connect Account** again, tick the permission to send email on your behalf, and **Update Service**. Test with **Email Templates > Test It**. |
| A photo shows its description instead of the image | The file is missing or misnamed | Check `git status` for deleted files, and that the file name in the HTML matches exactly |
| A change is not showing on the live site | GitHub Pages has not finished rebuilding, or the browser is showing a cached copy | Wait about a minute, then reload, or add `?v=1` to the address |
| The bare domain does not redirect to `www` | `CNAME` was changed, or the custom domain was cleared in Settings | Re-enter `www.visaeasesolutions.co.za` under **Settings > Pages** |
| `seo-check.js` reports a failure | A page was edited by hand, or a FAQ answer changed in one place only | Read the failing line, fix the value in `tools/seo-heads.js` or the FAQ, and run both scripts again |
| Email to info@ does not arrive | The Cloudflare routing rule points to the wrong inbox, or the destination address is unverified | Check **Cloudflare > Email > Email Routing** |
